Build a refund bot that asks before it acts

Add an AgentTrust checkpoint in front of every tool a support agent can call, so a $5,000 refund on a $120 order is blocked before any money moves.

What you will build

A customer writes "My order arrived late, can I have $40 back?". Your bot reads the ticket, looks up the order, issues the refund, emails the customer and closes the ticket. That bot is an agent: a loop that asks a model what to do next, runs the tool the model picks, and repeats.

Without protection, the model decides alone. By the end of this guide:

  • Every tool call is checked by AgentTrust before it runs.
  • A blocked call never runs. The bot gets a plain BLOCKED result and hands the ticket to a person.
  • If AgentTrust cannot be reached, the bot refuses to act.
  • Rules live in the Console, so you change limits without redeploying.
Prerequisites. Python 3.12, uv, git, and an account at console.agent-trust.tech. You do not need a model API key: the bot uses a scripted model, so every run is identical.
Already have the template cloned? The @harness quickstart is the short version of this guide: same result, only the changes.

How it works

You are not going to trust the model with anything that matters, so the check has to live outside the model. Each tool is wrapped with @harness from the AgentTrust SDK. The wrapper makes two checks with the gateway:

  1. Before the tool runs. The tool name and arguments go to AgentTrust, which compares them with your manifest and policy pack. If the answer is block, the tool never runs.
  2. After the tool runs. The result goes back to AgentTrust, which can withhold it, for example when it contains a hidden instruction. This cannot undo what the tool already did.
TermMeaning
ManifestKept in the Console. Lists the tools the agent may use and limits such as "refunds up to $1,000".
Policy packExtra rules in the Console, such as "a refund above $500 is a violation".
GatewayThe part of AgentTrust your code talks to. It answers allow or block.
@harnessAn SDK decorator. Put it on a function and it asks the gateway before and after the function runs.
Package name. Install agentrust-py and import agentrust_sdk. The PyPI package agentrust-sdk belongs to another company. Do not install it.

Write the checkpoint TODO 3

This is the core of the guide. governed_harness takes one tool and returns a protected version of it, using the SDK's @harness to do the asking. The code around it fixes four SDK defaults and behaviours:

  • "Needs review" is a no. The SDK lets it through by default.
  • A failing check stops the tool. The SDK runs the tool anyway by default.
  • Refusals become results. A refusal returns BLOCKED, an unreachable gateway returns UNAVAILABLE. The bot reads them like any other result instead of crashing.
  • It says who is asking. @harness reads the user only from keyword arguments. Without that line every Console event shows the user as unknown.

It also refuses to start without a gateway URL and key. Otherwise the SDK would send checks to localhost:8000, your own app, and run every tool unchecked.

That is the whole build. The tools, loop and model contain no safety logic: the checkpoint is a wrapper, switched on in one place.

Limits and trade-offs

  • Your key is limited by design. It can only ask questions, never change the manifest, mode or policies. Keep it in .env and rotate it in the Console if it leaks.
  • It fails closed. With AGENTRUST_FAILURE_MODE=closed an unreachable gateway refuses every tool and the ticket stays open. open runs everything unchecked during an outage.
  • It cannot wait for a human. A call that needs review is refused, not held and resumed. An agent key cannot read the reviewer's answer.
  • The check before does not read the customer's words. Injection is caught only by the check after, and only on a tool that returns the text.
  • The check after cannot undo. It withholds a result. It does not reverse a tool that already ran.
  • Two extra network calls per guarded tool. Latency was not measured here, so measure it for your plan before you guard read-only lookups in production.

Troubleshooting

When in doubt, run uv run refund-bot agenttrust check and ./scripts/todos.sh. They catch most setup mistakes.

The check says "rejected the key (HTTP 401)"

The key in .env is not an agent key. Copy the at_live_… key again. A long value starting eyJ is a login token. If you test with curl, send the key in an X-AgentTrust-Token header: Authorization: Bearer alone gets a 401.

A $5,000 refund or "delete all orders" is approved

The manifest has no declared tools (step 2), so AgentTrust skips the tool check. Open the agent, confirm the Tools line lists seven tools, and run the check again.

Every result says UNAVAILABLE

Your program cannot reach the gateway. Check AGENTRUST_GATEWAY_URL and your network. Nothing ran and the ticket stays open, which is the safe outcome.

The program stops with GovernanceNotConfigured

The gateway URL or key is missing from .env. This is deliberate: without them the checks would go to your own app.

The Console shows the user as unknown

The line that sets the user in step 7 is missing. @harness reads the user only from keyword arguments.
