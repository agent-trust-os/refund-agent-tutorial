@harness quickstart

Guard each tool with one decorator. AgentTrust is asked before the tool runs, a "no" stops it, and every decision is recorded in the hosted Console.

Overview

AgentTrust answers one question for every tool call: may this agent do this, with these arguments, right now? @harness puts that question in front of each tool. It is a decorator from the AgentTrust Python SDK. It asks the gateway before the function runs, runs it only on a yes, then sends the result back for a second check.

This page adds it to the Refund Bot template. It starts from a bot that happily refunds $5,000 on a $120 order and ends with that call blocked. The bot uses a scripted model, so you need no model API key and every run is identical.

Prerequisites. Python 3.12, uv, git and an account at console.agent-trust.tech. Want the longer walkthrough with the whole code on screen? Read Build a governed refund bot.

How it works

For each guarded call, @harness makes two requests to the gateway (/v1/runtime/pre-check and /v1/runtime/post-check) with the agent's own key. No model runs inside AgentTrust: the checks are deterministic rules.

  1. Pre-check. The tool name and arguments go to the gateway. It checks the tool is declared in the manifest and within its limit (a hard stop), then scores the policy rules.
  2. Decision. Approve or block. A block raises BlockedError and the tool body never runs.
  3. The tool runs, only after an approve.
  4. Post-check. The result goes to the gateway, which can withhold it, for example if it looks like a prompt injection. This cannot undo what the tool already did.
Three SDK defaults let a risky call through: block_on_review=False, raise_on_error=False and a failure mode of open. The wrapper you write in step 6 sets all three the safe way.

When to use it

Good fitWatch out for
Irreversible actions: money, deletes, outgoing messages. A hard stop before they run, whatever the prompt says.Two extra network calls per guarded tool. For read-only lookups that is latency for little value. Latency is not measured here.
Rules change in the Console with no redeploy. Every check is recorded with decision, reason and arguments.One more service. If it is unreachable you choose refuse (fail closed) or run unchecked (fail open). The SDK default is open.
Works under any agent loop. About 60 lines of Python.A call that needs a person is refused, not held and resumed.
Withholds a result that looks like an injection before the model reads it.The pre-check sees tool name and arguments, not the customer's words, and a post-check cannot undo.

In production guard the tools that move money, delete data or send messages first. Keep the guard on a tool that returns untrusted text, like read_ticket: it is what catches an injected ticket. This guide guards all eight tools so the Console shows the whole story.

Add the policy pack

The manifest cap is a hard stop. The policy pack adds score-based rules on the arguments. In Policies create a private pack, paste this file and activate it.

python/policies/refund-bot.yaml
name: refund-bot
version: "1.0.0"
description: >
  Rules for the Refund Bot. They check the proposed tool arguments at pre-check
  (execution.tools_called.0.arguments.*). Hard stops (an undeclared tool, an amount above the
  max_amount in the agent's manifest) come from the manifest, not from this pack.
environment: all
agent_id_patterns:
  - "refund-bot"

rules:

  - id: refund_reason_present
    description: "A refund must say why"
    severity: critical
    target: execution.tools_called.0.arguments.reason
    operator: not_empty
    conditions:
      - target: execution.tools_called.0.name
        operator: eq
        value: "issue_refund"

  - id: refund_over_500
    description: "A refund above $500 needs a person"
    severity: critical
    target: execution.tools_called.0.arguments.amount
    operator: lte
    value: 500
    conditions:
      - target: execution.tools_called.0.name
        operator: eq
        value: "issue_refund"

agent_id_patterns ties the pack to refund-bot. Each rule has a target (the path of a value in the proposed call, so execution.tools_called.0.arguments.amount is the refund amount), an operator and a value. conditions limits a rule to issue_refund, so lookups are never affected. A failing critical rule drops the policy score to 0 and the gateway blocks.

Write the checkpoint TODO 3

This is the core of the guide. governed_harness takes one tool and returns a protected version of it, using the SDK's @harness to do the asking. The code around it fixes four SDK defaults and behaviours:

  • "Needs review" is a no. The SDK lets it through by default.
  • A failing check stops the tool. The SDK runs the tool anyway by default.
  • Refusals become results. A refusal returns BLOCKED, an unreachable gateway returns UNAVAILABLE. The bot reads them like any other result instead of crashing.
  • It says who is asking. @harness reads the user only from keyword arguments. Without that line every Console event shows the user as unknown.

It also refuses to start without a gateway URL and key. Otherwise the SDK would send checks to localhost:8000, your own app, and run every tool unchecked.

Replaceonly that line with the code below. Keep the from __future__ line above it, and leave the TODO 8 comment at the bottom: it belongs to the direct API guide.

python/app/tools/governance.py
import functools
import os
from typing import Any, Callable

from ..core.config import get_settings

Tool = Callable[..., dict[str, Any]]


class GovernanceNotConfigured(RuntimeError):
    """AgentTrust is asked for, but the gateway url or the key is missing."""


def governed_harness(tool: Tool) -> Tool:
    """Guard a tool with ``@harness``: AgentTrust is asked before it runs, and again with what it returned.

    A refused call comes back as a BLOCKED result and a gateway that cannot be reached as UNAVAILABLE, so
    the agent loop and the model see a normal tool result instead of an exception.
    """
    settings = get_settings()
    if not settings.agentrust_gateway_url or not settings.agentrust_key:
        raise GovernanceNotConfigured("set AGENTRUST_GATEWAY_URL and AGENTRUST_KEY in .env (see .env-sample)")
    os.environ.setdefault("AGENTRUST_FAILURE_MODE", settings.agentrust_failure_mode)
    from agentrust_sdk import BlockedError, GatewayUnavailableError, harness

    guarded = harness(
        agent_id=settings.agentrust_agent_id,
        action=tool.__name__,
        base_url=settings.agentrust_gateway_url,
        api_key=settings.agentrust_key,
        block_on_block=True,        # a block stops the call
        block_on_review=True,       # so does "a person must look first": the SDK default lets it through
        raise_on_error=True,        # a failing check stops the call: the SDK default runs the tool anyway
    )(tool)

    @functools.wraps(tool)
    def call(*args: Any, **kwargs: Any) -> dict[str, Any]:
        kwargs.setdefault("user", "support-bot")        # @harness reads the user only from the keyword arguments
        try:
            return guarded(*args, **kwargs)
        except BlockedError as exc:
            return {"status": "BLOCKED", "tool": tool.__name__, "reason": exc.reason, "outcome": exc.outcome}
        except GatewayUnavailableError as exc:
            return {"status": "UNAVAILABLE", "tool": tool.__name__, "reason": str(exc)}
        except Exception as exc:                        # the check itself failed: do not run the tool
            return {"status": "UNAVAILABLE", "tool": tool.__name__, "reason": f"AgentTrust check failed: {exc}"}

    return call

Security and limits

  • The agent key reaches only the runtime checks. It cannot change the manifest, the mode or the policies. It lives in .env; rotate it in the Console if it leaks.
  • Governed mode refuses to start with no gateway URL or key, and no SSN or card number reaches the model.
  • It cannot hold a call for a person and resume it. A call that needs review is refused. The hosted gateway cannot call back to an app on your laptop, and an agent key cannot read the reviewer's answer.
  • The pre-check does not read the customer's words. Injection is caught only by the post-check, on a tool that returns the text.
  • A post-check cannot undo. It withholds a result; it does not reverse a tool that already ran.
  • No event id for an allowed call, so you cannot link a run to its Console event from the app. The direct API guide shows how.
  • Not measured here: latency per guarded call and your plan's limits.

Troubleshooting

Run uv run refund-bot agenttrust check and ./scripts/todos.sh first. They catch most setup issues.

"rejected the key (HTTP 401)"

The key in .env is wrong. Copy the at_live_… key again: a long token starting eyJ is a login token. The gateway reads the key from an X-AgentTrust-Token header. The SDK and the check send it, but a hand-written curl with only Authorization: Bearer gets a 401.

A $5,000 refund or purge_orders is approved

The manifest has no declared tools (step 3), so the gateway skips the tool check. Confirm the Tools line lists seven tools and run the check again.

Every result is UNAVAILABLE

The gateway cannot be reached and the failure mode is closed. Check AGENTRUST_GATEWAY_URL and your network. Nothing ran and the ticket stays open: the safe failure.

The Console shows the user as unknown

The kwargs.setdefault("user", …) line from TODO 3 is missing.

Checks look fine but Events stays empty

AGENTRUST_GATEWAY_URL may be missing, so checks went to your own app on port 8000. Governed mode refuses to start in that case. If you changed the code, put that check back.
