@harness quickstart

Guard each tool with one decorator. AgentTrust is asked before the tool runs, a "no" stops it, and every decision is recorded in the hosted Console.

Overview

AgentTrust answers one question for every tool call: may this agent do this, with these arguments, right now? @harness puts that question in front of each tool. It is a decorator from the AgentTrust Python SDK. It asks the gateway before the function runs, runs it only on a yes, then sends the result back for a second check.

This page adds it to the Refund Bot template. It starts from a bot that happily refunds $5,000 on a $120 order and ends with that call blocked. The bot uses a scripted model, so you need no model API key and every run is identical.

Prerequisites. Python 3.12, uv, git and an account at console.agent-trust.tech. Want the longer walkthrough with the whole code on screen? Read Build a governed refund bot.

How it works

For each guarded call, @harness makes two requests to the gateway (/v1/runtime/pre-check and /v1/runtime/post-check) with the agent's own key. No model runs inside AgentTrust: the checks are deterministic rules.

  1. Pre-check. The tool name and arguments go to the gateway. It checks the tool is declared in the manifest and within its limit (a hard stop), then scores the policy rules.
  2. Decision. Approve or block. A block raises BlockedError and the tool body never runs.
  3. The tool runs, only after an approve.
  4. Post-check. The result goes to the gateway, which can withhold it, for example if it looks like a prompt injection. This cannot undo what the tool already did.
Three SDK defaults let a risky call through: block_on_review=False, raise_on_error=False and a failure mode of open. The wrapper you write in step 6 sets all three the safe way.

Security and limits

  • The agent key reaches only the runtime checks. It cannot change the manifest, the mode or the policies. It lives in .env; rotate it in the Console if it leaks.
  • Governed mode refuses to start with no gateway URL or key, and no SSN or card number reaches the model.
  • It cannot hold a call for a person and resume it. A call that needs review is refused. The hosted gateway cannot call back to an app on your laptop, and an agent key cannot read the reviewer's answer.
  • The pre-check does not read the customer's words. Injection is caught only by the post-check, on a tool that returns the text.
  • A post-check cannot undo. It withholds a result; it does not reverse a tool that already ran.
  • No event id for an allowed call, so you cannot link a run to its Console event from the app. The direct API guide shows how.
  • Not measured here: latency per guarded call and your plan's limits.

Troubleshooting

Run uv run refund-bot agenttrust check and ./scripts/todos.sh first. They catch most setup issues.

"rejected the key (HTTP 401)"

The key in .env is wrong. Copy the at_live_… key again: a long token starting eyJ is a login token. The gateway reads the key from an X-AgentTrust-Token header. The SDK and the check send it, but a hand-written curl with only Authorization: Bearer gets a 401.

A $5,000 refund or purge_orders is approved

The manifest has no declared tools (step 3), so the gateway skips the tool check. Confirm the Tools line lists seven tools and run the check again.

Every result is UNAVAILABLE

The gateway cannot be reached and the failure mode is closed. Check AGENTRUST_GATEWAY_URL and your network. Nothing ran and the ticket stays open: the safe failure.

The Console shows the user as unknown

The kwargs.setdefault("user", …) line from TODO 3 is missing.

Checks look fine but Events stays empty

AGENTRUST_GATEWAY_URL may be missing, so checks went to your own app on port 8000. Governed mode refuses to start in that case. If you changed the code, put that check back.
