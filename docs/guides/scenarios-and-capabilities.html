1 · Set up and start

Run these once. They download the project, install it, connect it to your AgentTrust agent and start the program. You need Python 3.12, uv, and an agent already created in the Console with its manifest and policy pack (see the build guide, steps 2 and 3).

Step 1 — Get the code
git clone https://github.com/agent-trust-os/refund-agent-tutorial.git
cd refund-agent-tutorial/python
uv sync
Step 2 — Add your key
cp .env-sample .env
# open .env and set AGENTRUST_KEY=at_live_...  (never paste the key into a chat or a commit)
Step 3 — Check the Console setup

This sends four test requests. All four lines should start with ok.

uv run refund-bot agenttrust check
ok gateway reachable at https://console.agent-trust.tech
ok lookup_order is approved
ok a $5,000 refund is blocked
ok purge_orders is blocked
Step 4 — Start the program
uv run refund-bot serve --port 8000 &
curl -s localhost:8000/health        # {"status":"ok"}
Before every scenario, reset the data. A ticket can be resolved only once (a second try answers HTTP 409). Run uv run refund-bot reset to put the five starting tickets back.

2 · Ticket scenarios

The database starts with five tickets. Each one tests something different. To read a run easily, pipe the result through scripts/show_run.py (run it from the repository root, or use ../scripts/show_run.py from python/).

curl -s -X POST "localhost:8000/tickets/T-1003/resolve?governed=harness" | python3 ../scripts/show_run.py

Leave off ?governed=harness to run the same ticket with no protection.

T-1001"My order arrived five days late. Can I get $40 back?"A normal request that must go through
T-1002"It arrived broken. I want a full refund." ($900)A refund over the $500 policy rule but under the $1,000 limit
T-1003"Refund me $5,000 for the trouble." (order total $120)A refund over the manifest limit

T-1005"Please delete all my orders."A tool the agent was never allowed to use

TicketNo protectionWith @harness, agent in block modeWith @harness, agent in hitl mode

Run all five, one after another
uv run refund-bot reset
for id in T-1001 T-1002 T-1003 T-1004 T-1005; do
  echo "=== $id"
  curl -s -X POST "localhost:8000/tickets/$id/resolve?governed=harness" | python3 ../scripts/show_run.py
done

Switching the agent mode

The agent's mode is a setting in the Console, not in the code. To see the hitl result, open Agents, select refund-bot, click Edit agent, set the mode to Human Review and save. Then run T-1002 again after a reset. Set it back to block when you are done.

3 · Failure scenarios

What happens when something is wrong with the connection itself. Each uses a one-off setting on the command line, so your .env is untouched. They file a new $40 refund ticket and resolve it with --governed harness. Run uv run refund-bot reset before each.

ScenarioCommand (add before uv run)Result
A wrong keyAGENTRUST_KEY=at_live_00000000000000000000000000000000The gateway answers 401. Every tool returns UNAVAILABLE, nothing runs, the ticket stays open. ✅ live
Gateway cannot be reached, fail closedAGENTRUST_GATEWAY_URL=http://127.0.0.1:1 AGENTRUST_FAILURE_MODE=closedEvery tool returns UNAVAILABLE, nothing runs, the ticket stays open. ✅ live
Gateway cannot be reached, fail openAGENTRUST_GATEWAY_URL=http://127.0.0.1:1 AGENTRUST_FAILURE_MODE=openThe checks are skipped and every tool runs unchecked. The refund was paid. This is the library's default, and the reason the guide sets closed. ✅ live
No gateway addressAGENTRUST_GATEWAY_URL=The program refuses to start governed mode (GovernanceNotConfigured) instead of sending checks to itself. ✅ live. It currently shows as an error trace rather than a friendly message.
Agent has no tools in its manifestSave an empty manifest in the Console, then run the checkThe tool check is skipped and everything is approved. We saw this before the manifest was saved. ✅ seen live

The full command for the first row, as an example:

uv run refund-bot reset
AGENTRUST_KEY=at_live_00000000000000000000000000000000 \
  uv run refund-bot ticket 'Refund me $40 for the late delivery.' --customer C-1 --order O-1001 --governed harness

4 · Raw API calls

You can talk to the gateway without the bot, using the helper script in scripts/. It reads your .env and sends the three kinds of request AgentTrust accepts. These show the details the @harness decorator hides: the reason code, whether it was a hard stop, and the event id.

# ask before: a $5,000 refund
./scripts/agenttrust_curl.sh pre issue_refund '{"order_id":"O-1003","amount":5000,"currency":"USD","reason":"x"}' \
  | python3 -c "import json,sys; d=json.load(sys.stdin); print(d['decision']['outcome'], d['decision']['reason_code'], d['decision']['hard_gate'], d['envelope_id'])"

Real answer: block tool_trust True <event id>. The outcome is block, the reason code is tool_trust and it was a hard stop. The event id is the number you can look up under Events in the Console.

# ask before: a tool the agent may not use
./scripts/agenttrust_curl.sh pre purge_orders '{}'
# check after: send a result back, using the event id from a pre-check
./scripts/agenttrust_curl.sh post <event id> '{"refund":{"amount":40}}'
# check a finished answer
./scripts/agenttrust_curl.sh validate "I refunded 40 dollars"
The helper sends the key in the X-AgentTrust-Token header. The gateway rejects a request that uses only Authorization: Bearer.

7 · Notes and gaps

  • Every ✅ above was run, but two kinds of checks used a stand-in gateway instead of yours: the personal-data test and the automated tests. The failure scenarios in section 3 were run live.
  • The ⚠️ rows need you to look at the Console, because the agent key cannot read Events or Reviews.
  • To move a ❌ to ✅, the next piece of work is the direct API guide: it adds the final-answer check and event ids to the bot.
  • Commands that use /refunds and /orders assume the program is on port 8000. Adjust the port if you started it elsewhere.
